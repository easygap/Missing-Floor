# 없는 층 출시 전 확인 항목

기획서 §18.7·§19.9·§20.5·§21.5의 20개 항목을 모았다.
표의 ‘확인 방법’은 해당 항목을 통과했다는 뜻이 아니다.
실제 실행 결과는 [2026년 9월 22일 점검 기록](KOREAN_COPY_REVIEW_20260922.md)에 남긴다.

- **코드 검사**: 구현과 기획서의 값이 맞는지 확인한다.
- **계산 검사**: 시간차, 음량, 화면 범위 등을 스크립트로 계산한다.
- **사람**: 플레이하거나 장비로 측정해야 확인할 수 있다.

코드 검사와 계산 검사는 `Scripts/Validate-Project.ps1`로 실행한다.

## §18.7 조작

| 확인 항목 | 확인 방법 |

| 처음 하는 5명 중 4명 이상이 튜토리얼 없이 앉기·문 조용히 열기를 사용한다 | **사람** |
| 입력 후 소리가 나기까지 노크는 40ms, 다른 동작은 60ms 이하다 | **사람**(측정) + 코드 검사(지연 구조) |

난이도를 실제 메뉴에 연결했고, 현재 게임에 쓰이지 않는 예전 퍼즐 설정을 뺐다.

## §20.5 난이도

| 확인 항목 | 확인 방법 |
|---|---|
| 처음 하는 사람의 밤별 소요 시간 중앙값이 밤1 20~30분, 밤2 30~40분, 밤3 35~50분, 밤4 30~45분이다 | **사람** |
| 붙잡힌 횟수의 중앙값이 밤1은 1회 이하, 밤4는 3회 이하다 | **사람** |
| 같은 장소에서 10분 넘게 막히는 사람이 1명 이하다 | **사람** |
| ‘추격 없음’에서 진실 10개와 결말 A·B·C에 모두 도달할 수 있다 | 코드 검사(진행 조건) + **사람**(완주) |
| 난이도를 바꿔도 진행 중인 저장 파일을 불러올 수 있다 | 코드 검사(저장 분리) |

난이도는 사용자 설정에, 게임 진행은 저장 파일에 따로 기록한다.
난이도를 바꿨다가 되돌릴 때 적의 반응 단계가 남지 않는지도 실행 검사에 포함했다.
난이도별로 플레이 시간이 적당한지는 처음 하는 사람의 기록이 필요하다.

밤별 시간은 0.10.0(2026-10-14)에서 늘어난 분량을 더해 고친 설계 목표다. 확장 전에는 밤2 16~24분,
밤3 20~30분, 밤4 15~25분이었다. 둘째 밤에는 관리실 안쪽 방(4~5분), 셋째 밤에는 302호(8~10분), 넷째 밤에는
벽을 여는 단계가 늘었다. 실제 한 시간의 길이도 22·31·41·34분으로 같이 늘렸다. 처음 하는 사람의 기록은
아직 없어서 이 숫자를 통과로 보지 않는다.

## §21.5 소리

| 확인 항목 | 확인 방법 |
|---|---|
| 처음 하는 4명 중 3명 이상이 헤드폰으로 적이 있는 층을 알아맞힌다 | **사람** |
| 화면 표시 없이 4명 중 3명 이상이 적이 소리를 기다리는 상태를 알아챈다 | **사람** |
| 전체 플레이의 통합 음량이 −23 LUFS, 최대 실제 피크가 −1.5 dBTP 이하다 | **사람**(측정) + 계산 검사(합성음 잘림) |
| 동시 재생 상한을 넘거나 소리가 갑자기 잘리는 일이 없다 | 코드 검사 |
| 마이크 사용 여부에 따른 소음 판정이 §20.2의 범위를 벗어나지 않는다 | 코드 검사(상한) + **사람**(실제 마이크) |

`Scripts/Run-AudioPresentationProbe.ps1`은 벽에 가려진 적, 연속 추격,
여러 효과음의 겹침, 숨 참기, 연출상 소리가 잦아드는 구간을 재현한다.
실제 믹서의 음량을 읽고 `Saved/AudioPresentation/presentation-mix.wav`에 녹음한다.
`check_audio_presentation.py`는 무음 녹음과 파형 잘림을 검사한다.
`-FrameRate 30`, `-FrameRate 60`, `-FrameRate 120`으로 프레임별 동작을 비교할 수 있다.

`audit_tone_headroom.py`는 합성음 생성 단계의 음량을 계산한다.
최종 음량은 여러 소리가 함께 재생된 뒤 달라지므로, 전체 플레이의 LUFS와 실제 피크는 별도로 측정한다.

## 직접 확인할 것

**13개 항목**은 사람이 플레이하거나 장비로 측정해야 한다.
처음 하는 사람 5명의 플레이를 기록하면 조작 이해도, 기록 사용 여부,
밤별 시간, 붙잡힌 횟수, 오래 막힌 장소를 함께 확인할 수 있다.
그중 4명에게는 헤드폰으로 적의 위치와 상태를 알아챘는지도 확인한다.

배포 ZIP의 「테스트 도구/플레이테스트로 시작.bat」으로 켠 게임은 실행할 때마다
플레이 기록을 남긴다. `Scripts/summarize_playtest_records.py`가 그 기록을 모아 밤별
시간, 붙잡힌 횟수, 10분 넘게 막힌 자리, 앉기·문 조용히 열기·기록 화면을 스스로 쓴
사람 수를 위 기준과 견준다. 헤드폰으로 층을 맞혔는지, 기다리는 상태를 알아챘는지는
기록에 담기지 않아 [처음 플레이 기록](../.github/ISSUE_TEMPLATE/playtest_record.yml)의
질문으로 받는다. 보내는 방법은 [테스트 안내](TESTING.md)에 있다.

입력 지연은 고속 촬영이나 오디오 인터페이스로 재고, 전체 플레이 음량은
게임 출력을 녹음해 측정한다. 마이크는 같은 구간을 켠 상태와 끈 상태로 비교한다.
키보드와 게임패드로 각각 완주하고, ‘추격 없음’에서도 모든 결말을 확인한다.

0.10.0부터 밤은 403호 침대의 「아침까지 쉬기」로 끝난다. 밤 길이(32·42·55·48분)는 검사 경로로
어림한 잠정값이라 처음 하는 사람의 밤별 시간으로 다시 정한다.

직접 확인하지 않은 항목은 통과로 표시하지 않는다.
